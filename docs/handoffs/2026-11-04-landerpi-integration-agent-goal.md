## 1. 本轮目标与边界

最终产品是：手柄移动小车底盘，网页看相机；SO101 主臂通过离合和相对增量控制小车五轴从臂及真实夹爪；人工切换 observe/grasp，分别记录观察视角调整和抓取阶段；同一会话完成车端 sqlite3 原始录制、上位机校验同步、LeRobot 导出及网页读回。观察是用户手动调整相机视角，不是自主视觉策略。

本轮完成 Wave C 软件总集成：真实生产路由、会话、网关、录制及导出逻辑连通，只在设备和传输边界使用明确标记的模拟适配器。先验证底盘锁定的机械臂与夹爪 6D，再验证具备合格模拟底盘反馈的 9D 联合流程。硬件 profile 在缺少真实能力证据时继续拒绝输出。

本轮不 SSH、不打开真实串口/相机/手柄，不启动容器或机械臂栈，不启停已有实机服务，不发送真实运动，不烧录、不解除限位、不开展训练或推理。历史小幅运动授权不能扩展成连续旋转或固件烧录授权。硬件缺失不能阻止独立软件工作。

保留旧只读 profile/session 的非训练身份、全部 invalid session、原始数据、用户未提交修改及两个 `releases/training-monitor-*` 目录。保留 sqlite3，不强制迁移 MCAP。不要切换 `current`，不要覆盖本地定制 LeRobot。不得使用泛用 pkill、git reset/clean 或整目录覆盖来清场。不提交或推送，先交付可审查差异。

### 4.1 一个会话入口、一套状态和控制权

- 整合 `HybridSession`、`HybridPublicFacade`、channel/gateway、`HybridRecordingController` 和路由胶水；选定正式入口，避免路由各自实例化互不相干的会话或产生两份录制状态。保留现有兼容入口，禁止另开绕过租约的执行路径。
- 核对上位机主臂租约、车端租约和录制子任务：获取失败回滚，失效退出跟随，录制不再次申请冲突租约；标定、普通遥操作、联合遥操作、策略控制互斥。
- `/hybrid/control` 曾只传 action、丢弃 session/epoch；release/calibration/recording 也逐一检查。服务端必须校验相关操作的会话、纪元、权限和状态，旧客户端不能控制或释放新会话。急停采用明确的抢占规则，不能机械套用普通控制门禁导致有效急停被拒绝。
- 统一 public JSON、上位机、车端和 MCU 的 epoch 类型/范围；如需字符串会话与整数 wire epoch 映射，显式保存和校验。拒绝 bool、越界和有损转换，不静默强转。
- 统一 `(epoch, channel, source)` 序号语义。裁决“严格连续”与“单调递增”的差异，结合丢弃旧目标、队列合并及传输丢帧设计；不能因主动丢弃旧目标触发自相矛盾的序号故障。坏请求不能推进已接受序号，boot/epoch 切换后旧目标不得重放。
- 统一公开命令白名单；公开 HTTP 不接受伪造的 `received_mono_ns/deadline_mono_ns`。可信接收边界产生 deadline，本机传递保持原期限，跨主机扣除已消耗时效；排队和转发不能重新获得完整 TTL。不要比较不同机器的单调时钟。
- 对齐状态机、preview/align/armed/following、离合重建参考及恢复规则。重连、故障恢复、换标定后清目标并重新对齐；没有新鲜真实反馈不能启用硬件跟随。停止/保持不能统一替换为断力矩。

### 4.2 标定、反馈、ROS 与固件协议

- 保留主臂 Reader、从臂 Adapter、Mapper、Coordinator 的独立边界；主臂复用本地 SO101/LeRobot 校准逻辑，不把车臂伪装成 SO101Follower。主臂配置写入和力矩行为必须明确，不把 calibrate=False 当成只读。
- 核对主臂、从臂、主从映射以及底盘/手柄校准资产的版本、设备绑定、关节顺序、单位、哈希与原子保存。示例值不应被原样保存后当成已标定；失配必须阻止使能。
- 车臂只独立控制 joint1..joint5 与真实 r_joint；mimic 不增加控制维度。夹爪百分比通过单独映射转换，不能直接度转弧度。验证方向、比例、相对参考、滤波、速度/位置限制及回绕后机械/线缆限制。
- vendor joint_states 是命令缓存，odom_raw 是命令积分；它们不得升级成实测。反馈需要来源、设备/标定、有限值、逐关节年龄、完整性及扫描跨度。缺数据不补零、不用目标替代。
- 对接 T1 唯一串口 owner、有限超时、串行无事务 ID 请求、迟到回包隔离和安全监督。真实 readback 的 sample_seq、时效及校准绑定必须贯穿网关；不能把无事务 ID 协议描述成支持精确事务匹配。
- 复核 T2 function 0x0C 分配、帧长度/CRC/端序/计数边界、能力协商与版本兼容；让 T1 解码器与 T2 golden vectors 做真实跨模块字节测试。MCU 不验证 source/session_id 的限制由 owner 前门禁承担并如实记录。
- 复跑原生 C harness、golden vectors、补丁 apply/reverse/错基线拒绝。发现现有 ARM 工具链可用时可在隔离副本交叉构建；缺失就记录受阻，继续其他集成。主机 C 编译不等于 STM32 构建，AST 3.10 解析不等于 Humble/Python3.10 运行，均不得混称。

### 4.3 录制、阶段事件和数据事实

- 核对车端 agent 是否已有 `/recording/set_phase`；缺失则接入真实 recorder。必须验证 session/epoch、录制状态、阶段值，并在车端时轴落事件和 metadata；不能只让 HTTP 返回成功。phase 切换本身不发送动作。
- observe/grasp 是人工阶段，成功标签采用 success/failed/unknown 的正式定义，并兼容已选定 API 的 `success` 字段。统一前后端与原始事件，不套用仿真真值。
- 打通开始/结束 episode、暂停跟随、停止会话：结束先停控制再收尾，默认下一集重新接合；停止失败不得继续标正常完成；急停立即进入停止路径，不等待保存线程，覆盖收尾并发和旧请求竞态。
- 为真实经过的 base/arm/gripper 命令统一 TTL、session/epoch、source、seq、标定版本和确认事件。旧事件兼容必须明确版本和拒绝条件，不给缺字段事件补“可信”默认值。
- requested、gateway_accepted、driver_sent、controller_acknowledged、execution_observed 分开；只有唯一串口 owner 可证明 driver_sent，未获得回执或执行观测时写 unavailable。
- feedback_provenance 必须来自实际适配器与采样链，不凭 metadata 字符串把命令缓存变成可信来源。action 是正式发送目标，state 是真实反馈或合格且标明来源的估计，不能复制 leader 值。
- 同时保留锁底盘 6D schema 与联合 9D schema。无可靠底盘反馈的真机数据不得补零导成 9D；模拟 9D 数据保持明确模拟身份。旧只读数据仍拒绝训练导出。
- 两段 episode 的 observe/grasp 事件、manifest、视频 from_s/to_s 与曲线必须一致；复用 sqlite3、SHA256/READY/原子发布和已有导出保护，保留拒绝报告及源数据。
