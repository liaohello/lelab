## 1. 执行边界

- 当前应用、标定、相机和机械臂保持暂停，直到用户明确恢复并完成现场支撑检查。
- 本轮目标是依次完成三台标定、双臂真实观测复验、相机语义确认和 12 维策略审计。
- 只有 12 维策略审计通过后，才允许做真实观测影子推理；影子推理仍不得向 follower 下发动作。
- 实机运动需要另一项独立授权。标定、只读观测、相机映射或影子推理通过都不构成运动授权。
- 应用和硬件仍由同一个硬件租约互斥管理。一次只操作一台待标定设备，完成后停止并释放串口，再处理下一台。

### 阶段 2：双臂真实观测复验

1. 启动本地应用并打开 `/observe`。
2. 点击“从硬件角色填充”，只使用已保存角色和机器人记录，不重新打开串口。
3. 确认左右 follower 都加载各自的 `*_rig.json`，页面上没有 `raw_steps`。
4. 先静止采集至少 30 秒作为基线。
5. 在安全支撑下依次轻动左侧六轴，再依次轻动右侧六轴。每个关节记录动作前值、动作后值和变化量。
6. 全程观察左右表、相机、力矩、`actions_sent`、WebSocket 心跳和 fault。

验收：

- 左右各有六个有限数值，共 12 个。
- 五个关节显示度，夹爪显示 0–100% 或明确标成夹爪开合量；不得把夹爪称为度。
- 每个被轻动的关节都出现可识别的数值变化，左右两侧分别更新。
- 两侧 `bindings.<side>.unit` 都不是 `raw_steps`。
- 扫描期间 `actions_sent` 始终为 0。
- 力矩在观测期间持续采样且始终为 0；不能只使用启动瞬间快照。
- 相机最新帧年龄持续可读；建议本阶段门槛为 p95 < 250 ms、最大值 < 500 ms、无持续陈旧帧。阈值写入证据，不冒充硬件规格。
- 无 fault，停止后串口、相机和硬件租约释放。

需要保存的证据：

- 开始、轻动过程中和停止后的状态 JSON。
- `/ws/joint-data` 消息序列或等价 JSONL，含 `seq`、时间、12 维关节、相机年龄、力矩和 `actions_sent`。
- 每个关节的动作前后值及差值。
- 左右表分别更新、力矩为 0、`actions_sent=0` 的页面截图。
- 两路或三路相机截图及其索引、分辨率、时间。

当前代码缺口：扭矩只在会话开始时采样一次；观测消息没有显式 `seq` 和配置指纹；页面没有一键导出完整证据。硬件复验前应补齐这三项。

### 阶段 3：相机语义确认

1. 枚举 `/dev/v4l/by-id`、sysfs 名称、实际可打开索引和分辨率。
2. 对 index 0、2、4 逐个打开预览并保存首帧。
3. 每次只遮挡或指向一个物理相机；确认只有对应预览发生预期变化。
4. 记录物理安装位置、朝向和遮挡结果。肉眼无法区分的相机标记为 `unknown`，不得猜测。
5. 建立“物理机位 → 稳定设备标识 → 当前 cv2 index → 当前分辨率/FPS → 旧 ACT alias → 新语义名”映射。

建议的统一语义名是 `front`、`left_wrist`、`right_wrist`；旧名称通过 alias 保留，例如 `central`/`top` 和旧的 `right`/`up`。alias 只用于追溯，不代替物理确认。

通过条件：三台实际相机的索引、分辨率、物理机位和遮挡证据完整；0、2、4 是否稳定以及重新枚举后索引可能变化均已记录。

### 阶段 4：12 维策略只读审计

对候选策略逐项核验：

- 完整 checkpoint、config、预处理器、反处理器及权重哈希。
- `observation.state` 和 `action` 的维度、名称、顺序、数据类型。
- 五个关节角与夹爪各自的单位、零位、方向和安全范围。
- 相机 key、物理机位、分辨率、RGB/BGR 顺序和 FPS。
- 数据集 `meta/info.json`、任务文本、episode 数和 provenance。
- 归一化方式、统计量来源、processor 顺序和动作是绝对位置还是增量。
- checkpoint 训练时的机器人/仿真环境、相机参数、控制频率是否与当前台架一致。
- 严格加载和固定输入前向结果，但不得触碰串口。

当前结论：

- 现有 12 维 ACT 候选的关节名和相机形状看似一致，但来源是 `so101_dual_arm_mujoco`，原训练数据根不在本机，未证明标定、单位、方向和动作语义与当前四臂一致。
- 该候选的证据还显示同任务有效尝试中没有成功抓取/保持，不能作为已通过的能力证据。
- SmolVLA 数据使用 `top`/`left_wrist`/`right_wrist`、20 Hz 和不同分辨率，不是当前台架的直接匹配来源。
- 因此阶段 5 门禁当前为关闭状态。

审计通过的最低条件：完整数据与 checkpoint 来源可追溯；12 维名称/顺序/单位/动作语义明确；三相机物理映射和分辨率匹配；processor 和权重可严格加载；当前四臂的关节方向、零位和安全范围与训练环境有证据对应。

### 阶段 5：Jetson 双臂影子推理

仅在阶段 4 通过后执行：

1. 重启本地应用，确认只绑定回环地址，硬件租约空闲。
2. 在 Jetson 加载已核验的同版本策略和 processor，不更换本地定制 LeRobot。
3. 本地只读采集 12 维状态与三路相机，建立单调时钟 `seq`。
4. 上传真实观测，接收 12 维动作块，验证维度、有限值、会话/epoch、TTL 和乱序。
5. 动作只写日志和指标，不创建执行 sink，不改变 follower 力矩。
6. 记录往返延迟、上传/下载耗时、有效观测频率、动作块频率、动作年龄、队列深度/饥饿、拒绝数、错误、CPU/RAM/GPU 和运行时长。
7. 先做短程，再做持续运行；每次停止都清空动作队列并确认没有迟到动作被保留。

通过条件：全程 `actions_dispatched=0`、`actions_sent=0`、力矩为 0、无过期动作执行、无 fault、所有指标和日志可重放。

- 低速、小步长、小总位移限幅及动作 TTL 配置完成。
- 现场急停有效，机械支撑和作业空间已检查。
- 从最短动作、最小幅度开始，并先做仅观测和影子验证。

## 4. 前端优化方案

### 4.1 目标

把当前由多个独立页面拼起来的技术界面，整理成一条可追踪的双臂操作流程：

`设备身份 → 四台标定 → 双臂观测 → 相机映射 → 策略审计 → 影子推理 → 执行门禁`

### 4.2 信息架构

新增统一操作壳层，替换当前顶部栏堆叠多项操作：

- 左侧：LeLab 标识。
- 中部：`工作台`、`标定与观测`、`数据与训练`、`系统` 四个导航组；不再让八项导航都使用同一个 `Activity` 图标。
- 右侧：硬件租约、API/WebSocket 状态、HF 登录状态。
- 页面顶部固定“双臂就绪带”，同时显示：
  - 四台设备角色；
  - 左右 follower 标定状态；
  - 左右 leader 标定状态；
  - 三相机映射状态；
  - 策略兼容状态；
  - `actions_sent` 与当前租约。
- 未通过阶段显示 `未完成/阻塞`，不显示可执行按钮。

### 4.3 页面优化

| 页面 | 保留 | 优化 |
| --- | --- | --- |
| `/hardware` | 只读枚举、拔插事件、角色保存 | 用四张角色卡代替优先展示大量 sysfs 细节；显示串口、角色、标定文件、最近确认时间；路径放进折叠详情 |
| `/calibration` | 逐步记录零位和关节范围 | 增加左右/主从四格进度矩阵；URL 显式携带 rig 与 side；完成页展示六轴名、ID、范围、文件、SHA；支持回看而非只能重标 |
| 新增双臂工作台 | 现有 `/bimanual` 配置功能 | 把角色、标定、相机、策略和观测入口串成阶段时间线；保留专业配置在高级区 |
| `/observe` | 只读 WebSocket、相机、零动作 | 表单默认折叠；左右关节表固定六行并显示单位、当前值、1 秒变化和缺失/陈旧状态；相机改为枚举卡片和掩码映射；增加证据导出 |
| `/recording` | 双臂 URDF、相机健康、保存流程 | 采集只在标定、相机映射、配置核验全部通过后可用；沿用左/右颜色编码并突出动作状态 |
| 新增策略审计区 | 现有训练/推理页面 | 展示 checkpoint ↔ 数据集契约矩阵；明确显示 `兼容/不兼容/证据不足`；未通过时不提供影子启动按钮 |

### 4.4 视觉与交互约束

- 使用现有 Tailwind、shadcn、Lucide，不引入新的 UI 框架。
- 统一深浅色 token；消除 `/calibration` 的 slate 页面与 `/observe`、`/hardware` 的黑底页面之间来回跳色。
- 左侧固定青色强调，右侧固定琥珀色强调；危险操作只用红色，不与左右语义混用。
- 先显示“状态和下一步”，文件路径、SHA、原始字段放入可展开的技术详情。
- 关节表始终显示预期的 12 行，缺失值显示 `—`，不得用 0 填补。
- 相机卡片显示物理语义、索引、分辨率、FPS、最新帧时间和遮挡确认状态。
- 所有开始按钮前显示阻塞原因；按钮禁用不是唯一提示。
- 键盘可操作、焦点可见、颜色不是唯一状态信号。

### 4.5 先补的最小数据契约

1. `GET /calibration/inspection/{rig}/{side}`：返回端口、标定路径、SHA、六轴名/ID/范围、记录一致性。
2. `GET /observe/snapshot`：返回同周期 `seq`、单调时间、12 维状态、单位、相机年龄、力矩、`actions_sent`、配置指纹。
3. `POST /observe/evidence` 或本地导出：原子保存状态 JSON 和最新相机帧，不包含凭据。
4. 观测循环以低频持续读取 `Torque_Enable`，不得沿用启动快照。
5. 相机映射配置按稳定设备 ID 保存；cv2 index 只作为本次枚举结果，不作为永久主键。
6. 策略审计 API 只读返回 checkpoint、数据集、processor、相机与当前 rig 的匹配矩阵。
