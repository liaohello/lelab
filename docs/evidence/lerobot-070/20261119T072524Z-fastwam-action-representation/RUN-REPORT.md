### 4.1 三次失败的归因

- 第 1 次：**我的调度缺陷**。上一轮 `--gpu-wait` 只等"自己的 pid 从 compute-apps 消失"，
  而显存要再晚几秒才真正释放。现在等的是设备级显存。
- 第 2、3 次：**共享卡争用**。`chenhao` 的 ollama runner 常驻 19.1–19.6 GB，
  在我们预检通过、开始加载的几十秒内重新加载，31.74 GB 卡装不下 19 + 16 GB 两个任务。
  规则不允许停他人进程，也不能抢占，所以只能等；等到的窗口不足 134 s。

预检本身工作正常（第 3 次等了 361 s 才放行），但它挡不住"放行之后别人再回来"。

B 第 1 次失败暴露的是我自己的调度缺陷：上一轮 `--gpu-wait` 只等"自己的 pid 从 compute-apps 消失"，
而显存要再晚几秒才真正释放。现在的 `run_with_deadline.sh` 等的是**设备级显存**回到阈值以上，
并且启动前先做预检；预检超时会写 `exit_code=75`、`refused=insufficient_free_gpu_memory` 拒绝启动，
而不是硬上再 OOM。

规则上不能停他人的进程，也不能抢占共享卡，所以 B 只能等。剩余时间不足以等待并完成全流程，
因此本轮到此为止，B 与开发集筛选保留为待办。
