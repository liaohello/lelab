# LanderPi：夹爪自动区间标定与其余关节手动标定设计

状态：设计稿，已核对本地源码和调试页面；未执行硬件动作，尚非实现或实机验收。

## 1. 范围与现有入口

调试入口为 `http://127.0.0.1:18287/landerpi`。保留其“设备连接 → 主臂标定 → 树莓派从臂 → 配对预览”四步结构。

本次按以下范围设计：

| 对象 | 标定方式 |
| --- | --- |
| SO101 主臂，包括主臂夹爪 | 复用本地 LeRobot 手动流程与已有标定资产 |
| 车端 joint1..joint5 / ID1..5 | 参考 LeRobot 的参考姿态与手动范围采集，使用车端独立标定格式 |
| 车端 r_joint / ID10 | 自动采样、自动验证开合可用区间；第一次使用确认开合方向和安全搜索窗 |
| 主从映射 | 显式配对、方向/比例与相对参考；夹爪独立按百分比映射 |

如果以后需要 SO101 主臂夹爪也自动标定，应作为另一个硬件适配任务评估，不能把本设计的 ID10 协议直接用于主臂。

页面只操作向导和展示状态。Pi 的标定任务执行循环、超时和停止逻辑独立于浏览器运行；上位机管理主臂、标定资产和版本绑定。车端复用 MentorPi/Humble/Python3.10，代码与任务证据放持久的 `/home/ubuntu/shared/lelab_car`，原厂工作区作为只读依赖。

## 2. 已核查的参考与能力边界

- 本地 LeRobot `teleoperators/so_leader/so_leader.py` 及 `robots/so_follower/so_follower.py` 使用中位参考、half-turn homing、手动采集范围，再写入电机标定并保存。其 Feetech EEPROM、全部卸力矩及 wrist_roll 全编码范围的处理不能直接移植给车臂。
- 车端读数来自唯一 board owner 的 `GetBusServoState`，并使用隔离 bounded-read 补丁。`/controller_manager/joint_states` 的 vendor 缓存不参与端点判断。
- SDK 有 position、vin、temperature、angle-limit、torque-enable-state、position command、stop；没有在当前接口发现电流、负载或可验证的力矩/电流限制能力。位置命令的 duration 用于运动时长，不是夹持力限制。温度/电压也不能替代接触传感器。
- ROS node 中 `bus_servo_read_voltage/read_torque` 与 SDK 的 `bus_servo_read_vin/read_torque_state` 名称不一致。需要验证并修正隔离适配后才能声明这些诊断可用。当前 bounded-read 补丁不能自动解决这些名称问题。
- 存在 stop 指令不等于其实际停止/保持和延迟已验证；torque-enable-state 也不表示测得夹持力。
- vendor 角度基准为 `240° / 1000 tick`，夹爪反向配置另行保留。此基准不是对夹爪物理宽度、真实机械端点或 0..1000 全行程安全性的证明。

关键原则：**低速不等于低力，静止不等于到达机械端点。** 静止也可能来自物体阻挡、卡滞、未使能、命令未接受或旧反馈。

## 3. 网页交互

第 3 步分成三个连续区块：

1. **参考姿态与五轴手动标定**：显示当前 raw/rad、实际力矩状态、数据年龄；记录参考姿态，逐轴人工覆盖安全行程，展示 min/max/span 和质量检查。
2. **夹爪自动区间标定**：显示开合方向、安全搜索窗、当前 raw、目标 raw、进度、反馈年龄、端点证据和停止原因；按钮为“开始自动标定”“停止”“重新检测”“确认结果”。
3. **汇总与保存**：五轴分别完成，夹爪区间完成；显示测得区间、收缩后的工作区间、方法和证据，再保存 B 层并使旧 C 层映射失效。

主臂第 2 步继续链接已有 `/calibration` 页面。第 4 步验证新的 B/C 版本和无输出映射。

界面状态分开表达：`遥操作未使能`、`标定受控运动中`、`力矩状态`。夹爪正在自动运动时，不能只显示“执行输出关闭”。模拟环境必须有明显标记，不能凭 `/fixture/camera` 或夹具反馈显示实机已通过。

本次浏览器观察到第 3 步仍包含小幅往返测试的旧提示，工作树源码则已有手动范围采集和力矩按钮。实施前核验服务所用源码和 dist 哈希；页面观察不证明当前工作树已发布。

## 4. 五轴手动标定

采用 LeRobot 的交互形式，保留车臂自己的安全和单位语义：

1. 取得互斥标定租约，底盘锁定，普通遥操作/策略/录制不可并行。显示真实六路位置与设备身份，建立本次任务及采样 generation。
2. 用户将机械臂置于已知参考姿态，逐轴记录参考值。参考姿态与模型角度的对应必须明确；不能把任意舒服姿态静默定义成物理零位。
3. 用户逐轴覆盖安全可用行程。机构可安全回驱且已支撑时，可明确选择单轴或经确认的分组卸力矩；不能默认对整臂统一卸力矩。不能安全回驱的轴，使用人工控制的低速点动记录范围。
4. 后端持续采样并统计范围，不由前端轮询触发采样。只纳入有效、新鲜、序号未重复、身份匹配的真实读数；异常 raw 保留在证据中，不夹成正常值。
5. 逐轴检查有限值、方向、噪声、跨度、样本量与安全范围覆盖。一个固定的“80 tick”只能作为初步质量阈值，不能证明完整标定；重复轮询同一缓存样本不增加有效样本数。
6. 记录物理安全范围与更窄的工作软限位，供后端转换与限制。保留原厂坐标基准或记录显式变换，不写 SO101Follower 的 Feetech 校准文件，不自动改电机 ID/EEPROM。

退出手动模式前须处理实际力矩和参考位置。不能在手动摆动后直接恢复旧目标上的力矩，也不能取消时无条件自动加/卸力矩。采用经硬件验证的交接策略，用户仍需支撑时保持明确提示。

## 5. 夹爪自动标定的两种能力等级

### 5.1 当前默认：安全窗内自动校准

首次设置经过确认的搜索窗、开合方向和停止能力后，自动执行小步扫描、采样、往返验证、生成可用区间。此模式不需要用户手掰夹爪，不会主动把目标推进到未知机械硬限位。

搜索窗必须来自机构资料、已验证旧标定或首次受监督确认，且绑定设备和机构版本。未确定安全窗或方向时，拒绝自动扫描。不能把 YAML 的 0..1000、页面的 25..975 或历史小幅动作结果直接当作安全搜索窗。

到达预设窗边并且正常跟踪时，标记 `safe_window_edge`，它表示可用区间边界。出现命令继续变化而反馈静止、误差扩大或跟踪异常时，停止并标记 `blocked_or_endpoint_unconfirmed`，不得自动作为成功端点。恢复时从新鲜位置重新建立参考。

### 5.2 以后可扩展：未知机械端点自动寻找

只有存在并验证以下条件之一，才允许无人工端点判断地寻找未知机械端点：

- 可定位开/闭端点的限位或绝对开度传感器；或
- 独立确认的空载机构、可验证的安全接触/力限制能力，以及可区分接触与驱动失败的反馈和停止策略。

此模式可用位置平台、跟踪误差和接触信号联合形成候选，随后停止、退让并复验。仅增加电流读数本身仍不能区分物体与机械端点；不能以位置平台单信号替代上述能力。

当前 SDK 未证明具备此能力，默认 `unrestricted_endstop_seek=false`。若用户希望一次启动即自动找出完全未知的机械开闭极限，需要先补齐并实测相应硬件能力。

## 6. 自动任务状态机与执行顺序

```text
idle → precheck → baseline → opening_scan → opening_verify
     → closing_scan → closing_verify → repeatability_check
     → review → committed

任一步可进入 stopping → cancelled / fault / estop
```

- **precheck**：标定租约、设备/板型/ID10、唯一串口 owner、旧执行入口隔离、有效搜索窗和方向、空载夹爪、臂有支撑或保持能力、六路新鲜反馈、已验证停止策略。自动整区间运动超出旧“逐关节低速小幅”测试范围时，首次现场执行需明确该运动范围；设计与离线实现不需要提前索取授权。
- **baseline**：读取一段独立新样本估计噪声和稳定性；记录起点、关节状态、初始力矩和参考，不先跳中位或回零。开合方向来自机构/现场确认，不只依据 YAML 翻转字段。
- **opening_scan/closing_scan**：只向 ID10 发目标；每步先取新鲜位置再生成小目标，目标受搜索窗、单步幅度、raw 速度、动作时长、总时间和累计命令预算限制。step/settle/tolerance 等参数在受控低幅验证后冻结，不能默认把“1秒/8tick”当通用安全值。
- **verify**：边界必须有符合其能力等级的证据。误差增加、非响应、温度/电压异常、反馈失效即停止；没有端点确认能力时不能加大步长顶住试探。stop 后是否允许内退以及内退距离，都受硬件可停能力和当前反馈约束。
- **repeatability_check**：至少验证两次可用开闭位置的重复性、回差和稳定性，必要时使用同向接近减少回差影响；超过容差判失败，不取一组极值强行保存。
- **review**：显示结果分类、raw 开/闭值、可用区间、安全余量和重复性。用户确认方向和用途；无需手工录入端点。没有 mm 宽度实测时只显示归一化开合量。
- **committed**：服务端保存完整 B 层并返回版本/哈希。若五轴未完成则只保存任务草稿，不能把整个 follower 标为已标定。保存后不自动进入跟随。

全程监视非目标轴是否异常移动，但不为“保持”而盲目重发旧位置。发生移动时按验证过的整体停止策略处理，不能用未经验证的断力矩兜底。

## 7. 后端与车端边界

复用现有 `/ros-mobile/hybrid/follower-calibration/{action}` 代理及车端 `/calibration/follower/*`，新增能力作为同一标定任务的 action；具体路由名在实现前冻结，不新建第二套互不知情的租约/标定管理器。

建议职责：

| 模块/动作 | 职责 |
| --- | --- |
| `start/status/stop` | 一个标定任务、子阶段、token/generation、租约和取消 |
| `manual_reference/manual_finish` | 五轴参考姿态与人工范围采样 |
| `gripper_auto_start/gripper_auto_status/gripper_auto_stop` | 车端异步夹爪自动任务，限定 ID10 |
| `review/commit` | 从可信采样证据生成最终资产、校验并原子保存 |
| `FollowerCalibrationCoordinator` | 上位机业务协调，实际名字可复用现有模块边界 |
| `GripperRangeCalibrator` | Pi 上 ROS 无关的纯状态机/算法，通过适配器读写 |
| 现有 Board owner 与有界适配 | 唯一串口、反馈/命令/stop，硬件行为实测后声明能力 |

控制约束：

- 自动任务在独立 worker/timer 中推进，start 及时返回 job_id。HTTP handler 和安全停止不等待长扫描；不能持长锁 sleep 到完整运动结束才响应 stop。
- 标定 token 与普通控制互斥。ID10 自动子阶段与五轴手动卸力矩子阶段互斥；禁止自动夹爪任务触发所有关节加/卸力矩。
- 复用同一总线请求调度，避免后台六路扫描与标定查询互相争用或重复采样。为监护关节保留有界带宽，采样频率按实测总线负载配置。
- 任务 TTL/心跳由 Pi 单调时钟执行，断网或页面关闭后不能继续无人监管扫描。是否继续纯手动采样可另定，自动输出必须停止；超时检查不能只在下一次 HTTP 请求发生时才运行。
- cancel/fault 先停止输出和清队列，再存草稿和释放租约；不自动回到进入任务时的位置。真正 estop 的优先级高于保存。
- 无事务 ID 协议的迟到回包限制仍存在，查询超时/异常后拒绝继续使用污染链路。ROS future.cancel() 不代表底层 UART 事务已取消。
- 温度、电压、力矩状态必须先修正并验证方法映射及匹配逻辑；缺失时显示 unavailable，不伪造为正常。
- 服务端根据真实设备身份与采样日志创建 `measured`、时间、版本/哈希和有效标定结果。前端不得自行填写 measured=true、固定设备序列号、500 零位或测得范围后直接取得可信身份。

## 8. 区间、方向和主从映射

分别保存：

- `observed_closed_raw / observed_open_raw`：有证据的观察边界与证据类型。
- `usable_closed_raw / usable_open_raw`：收缩安全余量后的实际运行边界。
- `mechanical_limits`：只有独立端点证据时填写，否则为空。
- 搜索窗、噪声、回差、重复性、算法版本、停止能力证据、机构与设备绑定。

设 open 相对 closed 的 raw 方向为 `s=sign(open-closed)`：

```text
usable_closed = observed_closed + s × margin_closed
usable_open   = observed_open   - s × margin_open

u = clamp(leader_gripper_percent / 100, 0, 1)
raw_absolute = usable_closed + u × (usable_open - usable_closed)

raw_follow = follower_raw_reference
           + (leader_percent - leader_percent_reference) / 100
           × (usable_open - usable_closed)
```

raw_follow 最后执行有效范围、滤波和速度限制；接合离合前参考使用从臂实测值。已保存的开合端点保留语义，不按数值大小重新命名；数值排序只用于限幅。带符号跨度已包含开合方向，不能再重复乘一次方向造成双重翻转。

raw→rad 由 B 层统一转换，保留 vendor 坐标或显式软件零位变换。`percent` 不做度转弧度。没有实测几何/宽度拟合时，百分比仅表示校准区间的归一化开合量，不能宣称等比例毫米宽度。

现有 `TeleopMapper.gripper_target()` 的 `pulse_span_per_hundred_pct` 字段名与每百分比乘数的使用方式容易混淆，且有默认 6.0、默认零位和宽度模型。新标定应采用显式有单位字段或直接由开闭端点计算；设计兼容迁移并更新调用/测试，不能静默换单位或把默认几何当实测。

## 9. 数据与验收

沿用 B 层 follower 资产，并为每个关节增加独立方法与证据：五轴 `method=manual_range_capture`，夹爪 `method=auto_safe_window` 或经验证的 `auto_endstop_seek`。服务端产生最终文档；详细原始样本和任务日志独立保存并以 hash 引用。设备 ID、模型/转换版本、软限位、开闭方向、标定时间和回退版本必须可追溯。

`measured=true` 只说明获得真实采样，不足以表示所有关节合格；跟随门禁还须验证完整性、方法等级、确认状态和配套 mapping hash。旧标定未被原子提交成功替换时继续保留；新 B 层生效后旧 C 层必须失效并重新预览/对齐。

验收按以下顺序：

1. 纯算法：正/反向、噪声、量化、无响应、外部阻挡、重复缓存、越界、回差、无有效跨度、超时/取消、两次结果不一致、软限位与百分比映射；静止/失联绝不能单独成为成功端点。
2. API/任务：旧 token、并发自动与手动、长任务时立即 stop、租约过期、浏览器消失、总线故障、失败不覆盖有效资产、伪造 measured/设备身份拒绝。
3. 明确模拟环境：真实 React/后端状态机的自动与手动全流程；输出 sink 记录仅有 ID10 自动命令，其他轴无意外力矩/目标命令。模拟身份不获得真实标定资格。
4. 真机小幅验证：确认空载、搜索窗、方向、原始位置、stop/保持、限力/端点能力等级与监护；冻结参数后再运行完整允许区间。每个步骤保留目标与反馈，而非仅发布成功。
5. `18287/landerpi` 真实浏览器：手动参考/范围完成、自动启动、进度、停止、失败恢复、结果确认、保存、刷新读回和新版本配对预览。页面导航、重载或关闭不造成自动恢复运动。

本设计的实施交付应包含页面改动、Pi 自动任务、标定存储/映射兼容、离线测试和受控实机证据。当前文档不宣称上述功能已经实现。
